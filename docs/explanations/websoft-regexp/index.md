# Регулярные выражения через WebSoft.RegExp

`WebSoft.RegExp.dll` предоставляет серверному SP-XML Script обёртку над
`.NET System.Text.RegularExpressions`. Синтаксис шаблонов и строк замены
соответствует .NET, а не JavaScript RegExp.

!!! warning "Только серверный код"
    Получение .NET-объекта через `tools.get_object_assembly()` недоступно в
    клиентском коде.

## Сборки и версии

| WebSoft HCM Server | WebSoft.RegExp | `IsMatch(source)` |
| --- | --- | --- |
| `2022.1.3.434` | `1.22.6.8` | Нет |
| `2023.2.906` | `1.24.5.14` | Да |

Остальной прикладной API и проверенное поведение совпадают.

## Подключение и версия

```js
var regexp = tools.get_object_assembly('RegExp')
alert(regexp.GetVersion())
```

```log
1.24.5.14
```

`GetVersion()` вернёт `1.22.6.8` в сборке 434 и `1.24.5.14` в сборке 906.

## Общее изменяемое состояние

`tools.get_object_assembly('RegExp')` кеширует объект: повторные вызовы
возвращают один и тот же экземпляр. Значения `Pattern`, `Global`, `IgnoreCase`
и `MultiLine` сохраняются между последовательными серверными агентами до
перезапуска сервера.

`tools_web.reg_exp_init()` не создаёт изолированный объект. Он возвращает тот
же экземпляр, сохраняет текущий `Pattern` и устанавливает `Global`,
`IgnoreCase`, `MultiLine` в `true`.

!!! danger "Не полагайтесь на текущее состояние объекта"
    Другой серверный код может изменить шаблон и флаги. Явно задавайте нужное
    поведение перед операцией. Для поиска предпочтительна перегрузка
    `Execute(source, pattern)`: она не изменяет `Pattern`. Параллельная работа
    с методами, использующими общий `Pattern`, может приводить к гонкам.

После перезапуска сервера в проверенных сборках объект создаётся с
`Pattern = undefined` и тремя флагами `false`. Это начальное, а не постоянное
состояние кешируемого объекта.

## Шаблон и экранирование

Обратная косая черта внутри литерала SP-XML Script должна быть экранирована:

```js
var regexp = tools.get_object_assembly('RegExp')

var wrongPattern = '\d+'  // В DLL попадёт d+
var codePattern = '\\d+' // В DLL попадёт \d+

alert(regexp.Execute('123', wrongPattern).Count) // 0
alert(regexp.Execute('123', codePattern).Count)  // 1
```

```log
0
1
```

Если шаблон уже получен как данные из поля, файла или параметра, повторно
экранировать его не нужно.

## Флаги

| Свойство | Поведение |
| --- | --- |
| `IgnoreCase` | При `true` регистр не учитывается: `ББ` соответствует `бб`; при `false` учитывается |
| `MultiLine` | При `true` `^` и `$` обозначают начало и конец каждой строки; при `false` — всего текста |
| `Global` | Значение `true` или `false` ни на что не влияет: поиск и замена всегда обрабатывают все совпадения |

`MultiLine` не включает режим Singleline. Точка `.` не начинает
соответствовать переводу строки. В тексте с CRLF якорь `$` срабатывает перед
`\n`, но предшествующий `\r` остаётся в значении совпадения. При необходимости
учитывайте его в шаблоне, например `\r?$`.

Флаги можно задать внутри .NET-шаблона без изменения свойств общего объекта:

```js
var regexp = tools.get_object_assembly('RegExp')
var text = 'Info\nERROR\nDone'
var matches = regexp.Execute(text, '(?im)^error$')

alert(matches.Count) // 1
```

```log
1
```

Формы `(?-i)` и `(?-m)` отключают соответствующие опции, даже если свойства
общего объекта установлены в `true`.

## Поиск

Перегрузка `Execute(source, pattern)` доступна в обеих сборках, использует
переданный шаблон и не изменяет свойство `Pattern`:

```js
var regexp = tools.get_object_assembly('RegExp')
var text = 'Name: Alice, Age: 42'
var pattern = '(?-i)(?-m)Name:\\s*(\\w+),\\s*Age:\\s*(\\d+)'

var found = regexp.Execute(text, pattern).Count > 0
alert(found) // true
```

```log
true
```

Перегрузка `Execute(source)` использует текущий общий `Pattern`:

```js
var regexp = tools.get_object_assembly('RegExp')
regexp.Pattern = '(?-i)(?-m)\\d{1,3}'

var matches = regexp.Execute('+7 111 222 33 44')
alert(matches.Count) // 5
```

```log
5
```

### `IsMatch()` в сборке 906

В WebSoft.RegExp `1.24.5.14` доступна отдельная проверка наличия совпадения:

```js
var regexp = tools.get_object_assembly('RegExp')
regexp.Pattern = '(?-i)(?-m)\\d+'

alert(regexp.IsMatch('Age: 42')) // true
```

```log
true
```

В DLL `1.22.6.8` метода нет: вызов переходит в `catch` как `BmErrorInfo` с
текстом «Неизвестная ошибка». Для совместимого кода используйте
`Execute(source, pattern).Count > 0`.

## Замена

`Replace(source, replacement)` использует текущий `Pattern` и заменяет все
совпадения независимо от `Global`:

```js
var regexp = tools.get_object_assembly('RegExp')
regexp.Pattern = '(?-i)(?-m)Name:\\s*(\\w+),\\s*Age:\\s*(\\d+)'
var result = regexp.Replace('Name: Alice, Age: 42', '[$1]-[$2]')

alert(result) // [Alice]-[42]
```

```log
[Alice]-[42]
```

Строка замены использует синтаксис .NET:

- `$1`, `$2` — нумерованные группы;
- `${name}` — именованная группа;
- `$$` — один литеральный знак `$`.

Пример изменяет `Pattern` общего кешируемого объекта. Если вызывающему коду
нужно сохранить прежнее состояние, он должен отдельно восстановить значение
после успешного вызова и в ветви `catch`. Это не защищает от одновременного
изменения объекта другим кодом.

## Коллекция совпадений

`Execute()` возвращает `Websoft.RegExp.MatchCollection`. Для обхода используйте
`Count` и `Item(index)`:

```js
var regexp = tools.get_object_assembly('RegExp')
var matches = regexp.Execute('+7 111 222 33 44', '(?-i)(?-m)\\d{1,3}')
var match

for (var i = 0; i < matches.Count; i++) {
    match = matches.Item(i)
    alert(
        'Value=' + match.Value +
        '; Length=' + match.Length +
        '; FirstIndex=' + match.FirstIndex
    )
}
```

```log
Value=7; Length=1; FirstIndex=1
Value=111; Length=3; FirstIndex=3
Value=222; Length=3; FirstIndex=7
Value=33; Length=2; FirstIndex=11
Value=44; Length=2; FirstIndex=14
```

Индексы и длины считаются в кодовых единицах UTF-16: символ `😀` имеет длину `2`,
а индекс следующего за ним символа также равен `2`.

### Элемент `Match`

| Свойство | Значение |
| --- | --- |
| `Value` | Текст совпадения |
| `Default` | То же значение, что `Value` |
| `Length` | Длина совпадения в единицах UTF-16 |
| `FirstIndex` | Индекс начала с нуля в единицах UTF-16 |

Преобразование `Match` в строку также возвращает `Value`.

При отрицательном индексе или индексе `Count` метод `Item()` внутри DLL
возвращает `null`, который SP-XML-мост представляет как `undefined`.

Используйте явные формы `Item(index)` и `Count`.

## Группы захвата

`Match.SubMatches()` возвращает коллекцию захваченных групп без полного
совпадения. Индекс `0` здесь означает первую группу захвата, а не всё
совпадение:

```js
var regexp = tools.get_object_assembly('RegExp')
var matches = regexp.Execute(
    '+7-111-222-33-44',
    '(?-i)(?-m)(\\d)-(\\d{3})-(\\d{3})-(\\d{2})-(\\d{2})'
)
var match = matches.Item(0)
var groups = match.SubMatches()
var group

for (var i = 0; i < groups.Count; i++) {
    group = groups.Item(i)
    alert('Group ' + i + ': ' + group)
}
```

```log
Group 0: 7
Group 1: 111
Group 2: 222
Group 3: 33
Group 4: 44
```

Для прямого чтения одной группы доступна короткая форма
`match.SubMatches(index)`.

Ограничения обёртки:

- при отсутствии групп `Count` равен `0`;
- неучаствовавшая необязательная группа и группа, захватившая пустую строку,
  обе возвращаются как пустая строка;
- для повторяющейся группы сохраняется только последнее захваченное значение;
- имена групп не возвращаются, доступны только значения по порядку;
- выход за границы `SubMatches.Item()` даёт `undefined` через SP-XML-мост.

## Пустой шаблон и ошибки

Пустой шаблон создаёт совпадение нулевой длины в каждой допустимой позиции.
Для строки `ab` метод `Execute()` вернул три совпадения, а `Replace('ab', '_')`
вернул `_a_b_`.

Ошибочный шаблон, `null` вместо `Pattern`, `source` или строки замены приводят
к исключению. В обеих проверенных сборках SP-XML-мост представляет его как
`BmErrorInfo` с общим текстом «Неизвестная ошибка», поэтому из сообщения
нельзя надёжно определить исходную ошибку .NET.

## Ограничения библиотеки

- библиотека доступна только в серверном коде;
- `tools.get_object_assembly('RegExp')` возвращает общий кешируемый объект:
  `Pattern` и флаги сохраняются между агентами, а безопасная параллельная
  работа с изменяемым состоянием не гарантируется;
- `Global` не работает, `Execute()` и `Replace()` всегда обрабатывают все
  совпадения;
- `IsMatch()` отсутствует в сборке 434;
- явный тайм-аут регулярного выражения не задаётся, поэтому недоверенный шаблон
  может вызвать длительную загрузку процессора;
- `Execute()` полностью материализует совпадения и группы, поэтому расход
  памяти зависит от входной строки и числа результатов;
- обёртка групп не возвращает имена, позиции, признак участия и историю
  повторных захватов;
- ошибки .NET преобразуются SP-XML-мостом в общий `BmErrorInfo` с текстом
  «Неизвестная ошибка».

## Прикладной API

| Элемент | 434 | 906 | Назначение |
| --- | ---: | ---: | --- |
| `GetVersion()` | Да | Да | Версия DLL |
| `Pattern` | Да | Да | Общий текущий шаблон |
| `Global` | Да | Да | Хранится, но не используется |
| `IgnoreCase` | Да | Да | Сопоставление без учёта регистра |
| `MultiLine` | Да | Да | Многострочные `^` и `$` |
| `Execute(source)` | Да | Да | Все совпадения по `Pattern` |
| `Execute(source, pattern)` | Да | Да | Все совпадения без изменения `Pattern` |
| `IsMatch(source)` | Нет | Да | Наличие совпадения по `Pattern` |
| `Replace(source, replacement)` | Да | Да | Замена всех совпадений по `Pattern` |
| `MatchCollection.Count` | Да | Да | Число совпадений |
| `MatchCollection.Item(index)` | Да | Да | Совпадение по индексу |
| `Match.Value`, `Default` | Да | Да | Текст совпадения |
| `Match.Length`, `FirstIndex` | Да | Да | Длина и позиция совпадения |
| `Match.SubMatches()` | Да | Да | Коллекция групп захвата |
| `Match.SubMatches(index)` | Да | Да | Группа по индексу |
| `SubMatches.Count` | Да | Да | Число групп захвата |
| `SubMatches.Item(index)` | Да | Да | Значение группы |

Примеры проверены в серверных агентах WebSoft HCM `2022.1.3.434` и
`2023.2.906`.
