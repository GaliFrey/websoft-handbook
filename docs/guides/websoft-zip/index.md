# ZIP-архивы через Websoft.Zip

`Websoft.Zip.dll` доступна только в серверном коде WebSoft HCM. Получите
объект библиотеки через `tools.get_object_assembly('Zip')` и передавайте в её
методы файловые пути, полученные через `UrlToFilePath()`.

Руководство разделено по сборкам сервера. Публичный прикладной API одинаков,
но версии DLL и защита путей при распаковке различаются.

## Выбор сборки

- [WebSoft HCM Server 2022.1.3.434](434/index.md) — Websoft.Zip `1.22.6.8`;
- [WebSoft HCM Server 2023.2.906](906/index.md) — Websoft.Zip `1.24.5.14`.

## Краткое сравнение

| Характеристика | Сборка 434 | Сборка 906 |
| --- | --- | --- |
| Версия Websoft.Zip | `1.22.6.8` | `1.24.5.14` |
| Штатный журнал ошибок DLL | `xhttp_` | `zip_` |
| Обычные пути | Извлекаются | Извлекаются |
| Один уровень `../` | Извлекается | Извлекается |
| `../../` и `sub/../../` | Извлекаются | Блокируются |
| Абсолютный путь | Извлекается | Блокируется |

!!! danger "Распаковывайте только доверенные архивы"
    Обе проверенные версии допускают выход на один уровень выше каталога
    назначения через `../`. В сборке 434 проверки путей отсутствуют полностью.
    Защита сборки 906 блокирует часть опасных путей, но не устраняет уязвимость.

## Общее подтверждённое поведение

Для обеих сборок подтверждены следующие особенности:

- начальные `CharSet = Unicode (UTF-8)` и `CompressionLevel = 1`;
- необходимость закрыть создаваемый архив перед чтением его центрального
  каталога;
- рекурсивное добавление файлов через `AddDirectory()`;
- пропуск пустых файлов и пустых каталогов;
- два режима сжатия: `0` — Store, ненулевое значение — Deflate;
- сохранение `CharSet`, `CompressionLevel` и `GetError()` между обращениями к
  общему объекту библиотеки;
- сохранение старого текста `GetError()` после успешной операции;
- возврат `1` некоторыми методами, даже когда операция ничего не сделала.
