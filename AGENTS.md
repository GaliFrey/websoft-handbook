# Работа с проектом

- Общение и материалы — на русском, прямо и по делу.
- Перед изменениями изучать `README.md`, `MIGRATION.md` и `history.md`.
- Для обсуждения, анализа и ревью файлы не менять без запроса на реализацию.
- Использовать uv; проект — сайт документации, не Python-пакет.
- Сохранять простой Markdown и относительные ссылки. Не добавлять плагины и собственные компоненты без необходимости.
- Оригиналы в соседних `websoft-guide` и `WebTutor-examples` не изменять.
- Не считать перенесённый пример проверенным. Различать ожидаемый результат, локальные проверки и выполнение на стенде WebTutor.
- Черновики, шаблоны, секреты и реальные персональные данные не включать в `docs/`.
- После изменений выполнять `uv run --locked zensical build --strict` и проверять ссылки и вложения затронутых страниц.
- В конце итерации обновлять `history.md`: дата и время `ДД.ММ.ГГГГ hh:mm`, изменения, причины и проверки.
- Не запускать, не перезапускать и не останавливать dev-сервер без прямого запроса пользователя.
- Браузерную и визуальную проверку выполнять только по прямому запросу. В результате явно сообщать, проводилась ли она.
- Создание удалённого репозитория, push и публикация сайта требуют отдельного запроса пользователя.
